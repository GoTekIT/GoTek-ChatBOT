# D009 / H28 platform registry contract
Platform role distinct from workspace Owner/Admin, assigned only by trusted operator (no self-service escalation). Session identifies user; fresh platform membership checked on every platform request; workspace membership confers no platform privilege. Registry stores provider key references only, values resolved from server environment, never returned. Model has explicit capability list. Tenant grant capability must exist on model; runtime resolution rechecks provider enabled/model enabled/grant active. No API call or provider verification claimed merely because registry saved. No default chat access; support content grant remains unimplemented and default deny. Restore disables providers and revokes model grants.
API /api/platform/registry GET, /providers POST, /models POST, /grants POST, /providers/:id/state PATCH. Mutations audited with actor/reason, no key content. Platform scope RLS separate from tenant scope. UI contract /platform/providers: GoTek-specific provisional registry list, provider/model forms, capability fields, explicit error/loading/saving states; not HiChat parity. Full console design approval and acceptance remain open H28.05; this first backend slice does not close H28.

D011 lifecycle local/test: platform administrator looks up workspace by exact UUID, receives only id/name/status/created_at. Status mutation active/disabled requires reason and database lock, audits same transaction. Disabling removes workspace sessions without deleting business data; enabling requires fresh login. Platform has no broad tenant table RLS policy or chat access. UI has explicit lookup, status and reason, readback after save. In-flight work already dispatched before disable cannot be recalled; worker/provider checks block subsequent dispatch, not an unproven instantaneous distributed kill switch.
